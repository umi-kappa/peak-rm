# 0007 scoped CSS の境界は子のクラス指定でなくトークン再定義で越える

関連 Issue: #35 / #102 / #110

## 背景

親コンポーネントが子の見た目を変えたい場面が 2 つある。1 つは特定の子に個別のスタイルを当てたい場合、もう 1 つは hover や押下で面が上がったときに、配下の 3 次テキストをまとめて 1 段上げたい場合である。Vue の scoped CSS は親のセレクタが子の内部に届かないが、子コンポーネントの root には親の scope 属性が付くため、クラス名次第で意図せず結合が起きる。

## 決定

- 親の scoped CSS から子コンポーネントのクラス名を直接指定しない。個別に手を入れたい子には呼び出し側で class を渡し、自分が付けた名前に対してスタイルを書く
- 親の要素のクラス名を、自テンプレートで描画する子プリミティブの modifier 語彙（prop 値がそのまま root のクラスになるもの）と同名にしない
- 配下の 3 次テキストをまとめて上げたいときは、面が変わるスコープに限って色トークンを再定義する。再定義できるのはテキスト階調 3 段だけで、値は `:root` にある別のトークンを指す

## 検討した代替案

- **`:deep()` で子の内部クラスを指定する**: 子の内部構造への結合になり、子を改修すると親が壊れる。カスタムプロパティの継承は scoped CSS の境界を越えて slot の中まで届くため、クラス名を知らずに済む
- **BEM で modifier 名を接頭辞付きにする**: 衝突は避けられるが、短いクラス名という規約と両立しない。衝突の条件（自テンプレートで描画する子の root クラス）は限定的で、名前の使い分けで足りる
- **3 次テキストを上げる責務を子コンポーネントの prop にする**: `ExerciseCard` / `SessionSummaryCard` など `CardButton` 配下の全コンポーネントに prop を配ることになる。面の状態は親が持つので、親のスコープで一括して伝える方が自然

## 帰結

- 面の `transition` は配下へ継承されないので、`color` を宣言した側が `transition: color` も持つ
- トークン再定義の消費者は `CardButton` と `TimelineSetCard` の 2 つ。3 つ目が出たらこの 1 行を配り続けるのではなく、`TimelineSetCard` を `CardButton` + `BaseCard` へ寄せることを検討する
- 各論の規約は [docs/conventions.md](../conventions.md) の「スタイル（CSS）」節と「デザイントークン」節
