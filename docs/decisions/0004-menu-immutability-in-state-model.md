# 0004 メニュー不変条件を状態モデル（deep copy + `Readonly`）で担保する

関連 Issue: #33

## 背景

プロダクトの核心価値は「計画通りに実行させる（甘え防止）」であり、トレーニング中にメニュー（重量・目標回数・セット数・インターバル）を変えられないことが不変条件である。ボタンを `disabled` にする程度の UI 制御では、実装の追加や修正で穴が開きやすい。

## 決定

- セッション開始時に、メニュー設定画面で確定した menu を deep copy して `Session.menu` に焼き込む
- トレーニング画面は `Session.menu` だけを参照し、メニュー設定側の状態を見ない
- 型は `Session.menu: Readonly<Menu>` とし、変更をコンパイラで禁止する
- 不変性の対象はメニューに限る。実績回数とセットメモは「やっている途中は訂正できる」設計とし、履歴詳細だけ読み専用にする

## 検討した代替案

- **UI 制御（トレーニング画面に編集 UI を置かない）だけで守る**: 状態モデル上は変更可能なままなので、将来の画面追加や Import で不変条件が破れる。UI に現れない操作肢は状態モデルにも持たせない方が一貫する
- **参照共有（deep copy せずメニュー設定の状態を参照する）**: 次回に向けてメニューを編集した瞬間、実行中セッションの表示が変わる。開始時点の計画を固定できない
- **履歴の実績値も編集可能にする**: 過去のセッションには 1RM グラフや linear progression の判定が既に適用されており、遡及的な変更を許すとトレーニング史の一貫性が崩れる

## 帰結

- `useSession` の書き込みが不変条件を保証し、`sessionRepo` の書き込み境界でも空の `results` を拒否する
- 実行中状態を `shallowRef` + イミュータブル更新で持つ。`ref` の deep proxy を Dexie に渡すと structured clone が壊れるため、開始時は `toRaw` してから deep copy する
- 仕様の正本は [docs/spec.md](../spec.md) の「不変条件の実装方針」と「実績値の編集ポリシー」
