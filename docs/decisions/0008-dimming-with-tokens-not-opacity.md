# 0008 面の減光は `opacity` でなく専用トークンで AA を満たす

関連 Issue: #110 / #115

## 背景

インターバル画面のタイムラインは未実施セットを pending として薄く見せる。当初は要素ごと `opacity` で減衰させていたが、テキストも一緒に落ちるため、合成後のコントラストが 2.15:1 で WCAG AA（4.5:1）を大きく割っていた。

## 決定

- テキストのコントラストは AA（4.5:1）を満たす。3 次テキスト（`--color-text-tertiary`）は不透明な常設面（`--color-bg` / `--color-bg-pending` / `--color-bg-light`）のすべてで満たす値に置く
- 面を持続的に薄くするときは `opacity` を使わない。面と枠線に専用トークン（`--color-bg-pending` / `--color-line-pending`）を当て、テキストは 3 次のまま置く（4.69:1）
- hover / 押下で面が上がる箇所は、上がった先で 3 次テキストが AA を割るときだけ 1 段上げる（`--color-bg-light` へ上がる面は 4.53:1 で足りるので何もしない）

## 検討した代替案

- **`opacity` のまま値を上げる**: テキストが AA を満たす不透明度では面がほとんど薄くならず、pending の見分けがつかない
- **pending のテキストだけ `opacity` を打ち消す**: 子要素の `opacity` は親の合成後にしか効かないため打ち消せない
- **3 次テキストの値を全面的に上げる**: 常設面で足りるところまで上げると 2 次テキストとの階調が潰れる。#110 で 3 次を AA 通過値へ上げ、2 次で階調を再配分するところまでは行い、面ごとの差は専用トークンで吸収した

## 帰結

- 色トークンの値を動かすときは、テキスト 3 段（`--color-text` / `-secondary` / `-tertiary`）の間隔ごと見直す（下段だけ上げると階調が潰れる）
- 押下の瞬間フラッシュのような一時的な演出はこの決定の対象外
- 同じ行に並ぶアイコンは非テキスト基準（3:1）で単独では足りているが、見た目を揃えて一緒に上げる
