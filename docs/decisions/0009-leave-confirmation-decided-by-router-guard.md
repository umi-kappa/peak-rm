# 0009 セッションフロー離脱の確認は router ガードだけが行き先を決める

関連 Issue: #36 / #120

## 背景

トレーニング中・インターバル中にブラウザ / OS の「戻る」や AppBar の ← でフロー外へ出ると、実行中セッションが中断として確定する。誤操作 1 回で取り消せないため確認ダイアログを挟むが、セット完了の直後は記録の書き込みが進行中のことがあり、確認の答えと書き込みの完了の順序が入れ替わる。ページ側と router 側の両方が遷移を発行すると、離脱済みのフローへ再入するレースが起きた（#36）。

## 決定

- 離脱確認は `router/index.ts` の `beforeEach` が `useSessionLeaveConfirm` の `request()` で問い合わせる。ダイアログは `App.vue` が同じインスタンスの `pending` を見て描く
- キャンセル時は `session.settled()` で書き込みの完了を待ち、phase が元の画面のままなら遷移を取り消し、進んでいれば phase の画面へ redirect する
- ダイアログが関わった遷移の行き先はガードだけが決める。永続化の待ちを挟むページは、待っている間に離脱確認が開いたらフロー内の遷移を発行しない

## 検討した代替案

- **ページの `onBeforeRouteLeave` に置く**: Storybook では `RouterView` の外で描画されるためガードが無効になり、Story で検証できない
- **キャンセル時はページ側が `replace` で正しい画面へ進める**: 「戻る」で履歴の位置は既にホームへ移っており、そこで `replace` するとホームの履歴を上書きする。ガードの redirect は push なので「ホーム → 現在画面」に収まる
- **書き込み中は「戻る」を無視する**: ブラウザの履歴操作は止められない。URL だけ戻って画面が残る状態になる

## 帰結

- 非同期が 2 本（確認の答え・書き込みの完了）あるため、先後 × 分岐の全順序をトレースしてから変更する。パッチを重ねず、責務を 1 箇所（ガード）に絞った設計を保つ
- 待ちを挟まないページ（インターバル画面の `nextSet` / 中断）はダイアログが開いている間そもそも操作を受け付けないので対象外
- 仕様の正本は [docs/spec.md](../spec.md) の「セッションフローからの離脱」
